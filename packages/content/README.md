# @shubhvela/content

JSON content for Shubhvela in English, Hindi and Bhojpuri: UI strings, the rules corpus behind every "Why?" sheet, and (from A06 onwards) the interpretive corpus, festival texts, lessons and glossary. Everything is schema-validated in tests; nothing validates at runtime.

## Layout

- `ui/en.json`, `ui/hi.json`, `ui/bho.json`: flat maps with identical key sets (agent-written, never machine-translated). Namespaces (Phase A): `common tabs onboarding consent today band verdict panchang note upcoming charts dignity dasha sadesati family events vrat calendar reminders settings privacy disclaimer about errors`.
- `ui/design-tokens.json`: the single source of colours, type scale, spacing, radii and sizes (design.md 2). `scripts/gen-tokens.ts` writes `app/src/theme/tokens.ts`, `web/src/tokens.css` and `ui/token-contrast.json`; never edit those by hand. `npx tsx packages/content/scripts/gen-tokens.ts --check` fails when they are stale, and the generator throws on any type size outside `{26,22,20,18,17,15,13,12}` or any contrast pair below its minimum.
- `corpus/<domain>/<lang>.json`: arrays of snippets (`schema/snippet.schema.json`). English is the master; `hi.json` and `bho.json` are agent-written translations of it (owner decision 2026-10-29, see "Translations" below), `review: "draft"`. Every resolver still walks `FALLBACK_CHAIN` = bho → hi → en, hi → en, en per id and returns `{lang, fallback}` naming the language actually used, so the UI keeps its chrome language and never shows an empty string (`test/fallback.test.ts`).
- `corpus/planet-sign/en.json` (108), `corpus/planet-house/en.json` (108), `corpus/dignity/en.json` (14): the interpretive snippets behind the planet sheet (design.md 4). Ids use the lowercase English names of the engine locale tables, hyphenated because `snippet.schema.json` forbids dots: `<planet>-<sign>` (`mars-meena`), `<planet>-<house>` (`mars-7`), and for `dignity` the engine `DignityTag` names (`exalted`, `combust`, `retro`, `vargottama`, ...) plus `approx-lagna`, `approx-planet`, `moon-chart-mode`, `house-lord`, `sign-lord`. Every text is 40–90 words, level 1, `review: "draft"`, names its rule in `rule` and carries a `source` (Saravali for planet-in-sign, Phaladeepika for planet-in-house, BPHS / Surya Siddhanta / `convention` for dignity). `test/corpus-interpretive.test.ts` enforces counts, ids, word bounds and that each planet-sign text states the dignity `signDignity()` assigns.
- `corpus/lagna/en.json` (12, `lagna-<sign>`, 60–90 words, Brihat Jataka), `corpus/nakshatra-pada/en.json` (108, `nakshatra-<1..27>-<pada 1..4>`, 40–70 words naming the nakshatra lord, the pada's navamsa sign and the symbol; no naamkaran syllables), `corpus/dasha-pairs/en.json` (9 `dasha-maha-<PlanetId>` 50–80 words + 81 `dasha-<Maha>-<Antar>` 30–60 words using the engine planet ids `Su Mo Ma Me Ju Ve Sa Ra Ke`, i.e. exactly the `dasha-Ra-Ke` keys the daily note emits; each antar text states the antar lord's Parashara relation to the maha lord), `corpus/transit/en.json` (39: `transit-<saturn|jupiter|rahu>-<1..12>` from the Moon + `sade-sati-phase-1..3`), `corpus/daily/en.json` (105 one-to-two-sentence fragments, one per `DAILY_FRAGMENT_KEYS` entry of `packages/engine/src/rules/daily.ts`: `chandra-bala-<1..12>`, `tara-bala-<1..9>`, `tithi-<1..30>`, `nakshatra-<1..27>`, `vara-<0..6>`, the 7 special-yoga keys, `bhadra-earth|heaven|patal`, `panchak`, the 6 Sade Sati state keys and `day-strength-strong|mixed|weak`). Every daily fragment's `params` equals the engine's `RULE_PARAMS[ruleIdOfKey(id)]` and may interpolate only those names; values are raw engine data (UTC ms, 1-based sign/nakshatra numbers, planet ids) that the UI formats before calling `interpolate`. `test/corpus-interpretive.test.ts` enforces all of this.
- `corpus/festivals/<lang>.json` (`schema/festival-text.schema.json`; 102 = one per slug of `packages/engine/data/festival-rules.json`, id `festival-<slug>`): `name` from the engine table, `rule` = the same sentence as `corpus/rules` `festival-<slug>`, `what` 80–150 words of what people do, `conventionNote` the Purnimanta/Amanta, timing or North/South note. `corpus/vrats/en.json` (12, snippet schema, id = engine ruleId `vrat-<VratFamily>`, e.g. `vrat-vinayakaChaturthi`; `rule` = timing sentence, `text` 80–150 words). `corpus/glossary/<lang>.json` (`schema/glossary.schema.json`; ≥ 150, plain slug ids such as `tithi`, `rahu-kaal`, `sade-sati`, `mesha`, `rohini`, `kartik`; `term_dev` Devanagari, `term_lat` Latin, `meaning` one line ≤ 160 chars, `related` glossary ids). `test/corpus-ritual.test.ts` enforces counts, ids, word bounds, that every engine sign/planet/nakshatra/tithi/month name and every Sanskrit term in `ui/en.json` and `corpus/rules/en.json` (its `LINKED_TERMS` table) has a glossary entry. Loaders: `loadFestivals(lang)` / `festivalText(slug, lang)`, `loadGlossary(lang)` / `glossaryTerm(id, lang)`.
- Phase B (B02): `corpus/yogas/en.json` (40, level 1, 50–90 words: one per engine `YOGA_RULE_IDS` id — 31 `yoga-<id>` + 7 bhanga ids — plus `yoga-kala-amrita` for the reversed Kala Sarpa and `yoga-none` for the empty card; "formed / cancelled" vocabulary), `corpus/koota/en.json` (`koota-<id>-<1|2|3>` for the 8 kootas: level 1 one sentence for the free summary, 2 a paragraph, 3 the full explanation; plus the 4 `KOOTA_EXCEPTION_IDS` at level 3), `corpus/mangal/en.json` (`mangal-dosha`, `mangal-dosha-none`, the 6 `mangal-cancel-*` rows), `corpus/muhurat-activities/en.json` (the 14 `muhurat-<activity>` rule tables, the 10 `muhurat-rule-<rule>` chip texts, `muhurat-ranking` for the N18 order), `corpus/naamkaran-names/en.json` (`schema/naamkaran-names.schema.json`; 108 entries `nakshatra-<n>-<pada>` with the engine syllable and 3–5 names `{dev, lat}`, no meanings; `note` names the almanac substitution for syllables such as ङ, ष, ण, ञ that no name begins with; English-only, `loadNaamkaranNames(lang)` / `naamkaranNames(nakshatra, pada, lang)` fall back with the flag). `test/corpus-phase-b.test.ts` enforces ids against the engine, word bounds, params = `ruleParamsB(id)` and the register. Phase B UI namespaces: `pro ads unlock vargas kp ashtakavarga varshaphal muhurat travel naamkaran match share pdf report` (+ `disclaimer.report`); `test/completeness.test.ts` pins the spec section 9 matrix rows verbatim and the M2 / N5 / design 5 copy.
- Phase C (C02): `corpus/lessons/en.json` (`schema/lesson.schema.json`; 21 lessons `lesson-01..21`, 5 minutes, bodies 350–450 words in ≥ 4 paragraphs, the last one a "try it" instruction; `terms` = glossary ids; `tryIt {route, label}` = the expo-router route and ui key of the card to open; `unlocksLevel` 2 for lessons 1–12, 3 for 13–21). Bodies use only the `{placeholders}` listed in the schema's `placeholders` block, mirrored by `LESSON_PLACEHOLDERS` in `src/lessons.ts` (57 names: `moonSign`, `lagna`, `nakshatra`, `mahaLord`, `saturnHouseFromMoon`, `todayTara`, `rahuKaalToday`, `savLagna`, `kpLagnaSubLord`, ...); the app resolves them from `ChartData`, `dasha()`, `varga(D9)`, `ashtakavarga()`, `yogas()`, `kp()`, `panchang()`/`goodHours()` at the profile place and `tithiEventDates()`, passing `lesson.lagnaUnknown` / `lesson.noYoga` when a value cannot be computed. Loaders `loadLessons(lang)`, `lesson(id, lang)`, `lessonPlaceholders(l)`, `renderLesson(l, values)`. Glossary +47 (264) so every lesson term resolves. `corpus/rules/en.json` +10: `prashna-*` (3) and the Ask-my-chart system rules `ask-system-*` (6) + `ask-label` — the C04 prompt builder reads them via `ruleText(id, lang)` so the model's rules are the Why?-sheet rules. `corpus/daily-third/en.json` (32): third-person variants of the `daily` fragments that say "your", same ids, `params = ['name', ...]` — Family Today renders `lookup('daily-third', id, lang) ?? lookup('daily', id, lang)` for non-self profiles (carry-over B-REVIEW-MEDIUM-2). Phase C UI namespaces `learn lesson glossary journal prashna ask backup deeplink` (+ `widget.*`/`tts.*` additions, `settings.backup`, `settings.askModel*`); `test/completeness.test.ts` pins `ask.label` = "AI explanation from your chart — can be wrong", the device-gate row, "2.6 GB", "Download paused — reconnect to Wi-Fi", the five mood words and "for reflection, not proof". `test/corpus-phase-c.test.ts` enforces all of the above.
- `corpus/rules/en.json`: one entry per engine rule id (`RULE_IDS` in `packages/engine/src/rules/ruleIds.ts`): `text` is the one-sentence rule, `source` the classical text (or `convention`), `params` the engine inputs the "Why?" sheet lists. Festival entries are regenerated from `packages/engine/data/festival-rules.json` by `scripts/gen-festival-rules.ts`; the other entries are hand-written.
- `schema/`: `snippet`, `ui`, `festival-text`, `lesson`, `glossary` JSON schemas (draft-07 subset; validated in tests by `test/lib/validate.ts`). `ajv` is deliberately not a dependency: the mini validator covers exactly the draft-07 subset these schemas use (`type`, `required`, `properties`, `additionalProperties`, `propertyNames.pattern`, `enum`, `items`, `minItems`, `minProperties`, `minLength`, `minimum`/`maximum`, `pattern`), and keeping it avoids a runtime-capable validator in a package that validates only in tests (carry-over A-NIT-2, closed in A09).

## API (`src/index.ts`)

- `loadUi(lang)` → the flat string map.
- `t(ui, key, params?, lang?, fallback?)` → interpolates `{param}`; with `params.count` picks `<key>_one` / `<key>_other` (en: one = 1; hi/bho: one = 0 or 1). Missing keys return the key.
- `loadCorpus(domain, lang)` → `{snippets, lang, fallback}`; `lookup(domain, id, lang)` / `ruleText(ruleId, lang)` → `{text, lang, fallback, snippet}`; `festivalText(slug, lang)` / `glossaryTerm(id, lang)` → `{item, lang, fallback}`. Each walks `FALLBACK_CHAIN[lang]` per id and returns the first language that has it, with `fallback: true` when that is not the requested language.
- `pseudoLocale(ui, 1.3)` → every string padded to +30 % visible length for the layout snapshot tests (design.md 7).

## String conventions

- Keys: `namespace.camelCase`, nested groups with further dots (`band.seg.rahu-kaal` mirrors engine ids). Params `{name}`. Plurals `_one` / `_other`.
- Constrained-box key convention (enforced by `test/completeness.test.ts` on visible code points, `{param}` counted as 6): `tabs.*` ≤ 12 · `*_band` (inline band label) ≤ 10 · `*_tag` and `dignity.<key>` tags ≤ 14 · `*_chip` ≤ 18 · `*_col` (table header) ≤ 20. Everything else wraps.
- Register (spec 7, design 7): Hindi respectful आप, Khari Boli; Bhojpuri respectful रउआ / राउर, होला / करीं / बानी / नइखे, Devanagari, no Maithili forms, Latin technical terms on first mention. Avoid = `टालें` (hi) / `बचीं` (bho). `test/register.test.ts` checks Devanagari dominance, pronoun register, Maithili forms, forbidden phrases (`packages/content-tools/forbidden.json`) and percentage claims in every language.
- Weekday, month, sign, nakshatra and planet names come from the engine's locale tables, not from these files.

## Translations (hi / bho)

Every corpus domain except `naamkaran-names` has a complete `hi.json` and `bho.json` next to its `en.json` (18 domains, 1,434 records per language, 2026-10-30), written by hand by the same agents that wrote the English master and the UI strings; no machine-translation API was used (the `corpus-translate.yml` Action is superseded). Only the human-readable fields are translated (`text`; festivals `name` / `what` / `rule` / `conventionNote`; glossary `meaning`; lessons `title` / `body` paragraph for paragraph); `id`, `rule`, `source`, `params`, `level`, `review`, `slug`, `term_dev` / `term_lat` / `related`, `n` / `terms` / `tryIt` / `unlocksLevel` are byte-identical to English, every `{placeholder}` and `\n` survives in the same count, digits stay Latin, and the register is the one of the UI files (Hindi आप / Khari Boli; Bhojpuri रउआ / राउर, होला / करीं / बानी / नइखे, Devanagari, no Maithili forms). Registration is two static imports and `hi:` / `bho:` keys per table in `src/registry.ts`; `load.ts` is unchanged. Snippet domains and festivals may be edited record by record (a deleted record falls back per id); the glossary and the lessons are rendered as whole files and must stay complete. `test/translations.test.ts` enforces all of this: per-record parity for every registered hi/bho table, `fallback: false` in the requested language for every English id (it `T99`), per-item wording the UI depends on (engine festival names, dignity tags, koota names, UI screen names in lessons, the Ask-my-chart label). How the files were produced, the register rules, how to review or edit a record and how the owner's review packs map to files: `docs/CONTENT-TRANSLATION.md`.

## Tests

`npm test -w packages/content`: schema validity, identical key sets and params, length budgets, dignity vocabulary (design.md 4), honesty markers, register and forbidden content, rules coverage of `RULE_IDS`, hi/bho corpus parity and completeness (`test/translations.test.ts`), token contrast in both themes, generated token outputs current.
