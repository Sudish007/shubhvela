# Shubhvela · Google Play release checklist

For the owner, working from a **personal** Play Console account. Package `com.shubhvela.app`, free app with ads
(AdMob) and in-app purchases. Tick the boxes top to bottom; each requirement names the Play Console Help page it
was verified against and the date of verification. Items that could not be verified against a current help page are
marked **unverified**. Store texts are not in this file: paste them from `app/playstore-assets/store-listing.md`
(written by the build run's d04 step), see the table at the end.

Verified on 2026-10-29 unless a line says otherwise. Help pages change; re-open the cited page before the final submission.

---

## 0. Before you open Play Console

- [ ] Developer account is registered and identity-verified (personal account).
- [ ] Payments profile created (Monetize with Play → Setup → Payments profile) so in-app products can exist.
- [ ] Upload keystore exists and is backed up off the machine (see `release/README.md`; the keystore and
      `release/KEYSTORE-INFO.txt` are gitignored on purpose). Requirement for the upload key: RSA 2048-bit or more,
      stored in a `.jks`/`.keystore`. Source: [Use Play App Signing](https://support.google.com/googleplay/android-developer/answer/9842756) (2026-10-29).
- [ ] The web site (https://sudish007.github.io/shubhvela/) is live with a **privacy policy** page and a
      **data deletion** page (paths come from the web run; confirm them before pasting URLs). Requirements for the
      privacy policy URL: public https URL with a valid certificate, reachable worldwide without login, a normal
      web page (not a PDF), specific to this app. Source: [Prepare your app for review](https://support.google.com/googleplay/android-developer/answer/9859455) (2026-10-29).

## 6. Build requirements

- [ ] **Target API level.** New apps and updates must target **Android 16 (API 36) or higher from 31 August
      2026**; until then API 35 is the floor (new apps and updates since 31 Aug 2025). Shubhvela targets **36**
      (`app/app.json` → `expo-build-properties.android.targetSdkVersion: 36`, compileSdk 37), which satisfies
      both. Source: [Target API level requirements for Google Play apps](https://support.google.com/googleplay/android-developer/answer/11926878) (2026-10-29).
- [ ] **Upload an AAB**, not an APK. `scripts/build-apk.ps1` produces the APK for emulator checks; the
      release bundle is `release/*.aab` (gitignored). `versionCode` must increase every upload (max 2,100,000,000);
      current `app.json` versionCode 4. Source: [Create and set up your app](https://support.google.com/googleplay/android-developer/answer/9859152) (2026-10-29).
- [ ] **Play App Signing.** New apps are enrolled automatically with Google-generated keys (quantum-ready hybrid
      signing); you only keep the **upload key**. Register the Google-held signing-key SHA-256 (not your upload
      key) with any API provider that checks fingerprints — none is needed today (no Google Sign-In, no Maps).
      Source: [Use Play App Signing](https://support.google.com/googleplay/android-developer/answer/9842756) (2026-10-29).
- [ ] **64-bit.** Google Play requires 64-bit support; the bundle must ship `arm64-v8a` for every `armeabi-v7a`
      library (Expo/React Native's default ABI set does). Check the uploaded bundle in Play Console → release
      details → "64-bit" warning absent. Source: [Support 64-bit architectures](https://developer.android.com/games/optimize/64-bit) (2026-10-29).
- [ ] The uploaded bundle carries the new brand launcher icon, splash and notification icon (d-ship verifies on
      the emulator and in the APK; `node scripts/gen-brand-assets.mjs --check` exits 0 on the release commit).

## 7. Testing tracks and the personal-account rule

Personal accounts created after 13 November 2023 **must run a closed test with at least 12 testers opted in
continuously for 14 days** before they can apply for production access. Production and pre-registration stay
disabled until then. Source: [App testing requirements for new personal developer accounts](https://support.google.com/googleplay/android-developer/answer/14151465) (2026-10-29).

- [ ] **Internal testing** (optional, recommended first): Test and release → Testing → Internal testing; upload
      the AAB, add your own e-mail list, install via the opt-in link. Not subject to app review or Data safety.
- [ ] **Closed testing**: complete the whole App content page and the store listing first ("complete app setup"),
      create a closed track (e-mail list or Google Group), roll out, send the opt-in link.
- [ ] Recruit **12 or more** testers (family, friends, the Hindi/Bhojpuri-speaking target users). Tell them in
      writing to stay opted in for **14 days without leaving**. Keep a log of feedback: the production-access
      form asks you to summarise it.
- [ ] After 14 days with ≥ 12 opted-in testers: Dashboard → **Apply for production** and answer the three
      sections (About your closed test / About your app / Production readiness).
- [ ] **Open testing** becomes available only after production access is granted.
- [ ] **Production**: create the release, choose countries, roll out (staged roll-out optional).

## 10. AdMob and `app-ads.txt`

- [ ] Create the production AdMob app (the repo still carries Google's **test** app ID
      `ca-app-pub-3940256099942544~3347511713` and test unit IDs in `app/app.json` → `extra.admob`; `live: false`).
      Replace them in the build run before the production AAB.
- [ ] `app-ads.txt`: AdMob crawls `https://<developer-website-host>/app-ads.txt` — the **root of the hostname**
      taken from the Play listing's developer website. A GitHub Pages *project* site
      (`sudish007.github.io/shubhvela/`) cannot serve a file at the root of `sudish007.github.io`, so the file can
      only be verified once the site moves to a custom domain (or a `sudish007.github.io` *user* site hosts the
      file). Until then AdMob reports the file as not found (effect on ad serving: **unverified**). Use the
      personalised snippet AdMob shows you (format `google.com, pub-XXXXXXXXXXXXXXXX, DIRECT`); the file must be
      plain text at the IAB `app-ads.txt` format, and the Play listing's developer-website URL must point at that
      host (changes take up to 24 h to be picked up).
      Source: [Set up an app-ads.txt file](https://support.google.com/admob/answer/9363762) (2026-10-29).
- [ ] Set AdMob ad-content rating to match the Play content rating (the IARC help page says ads must fit the
      rating; use AdMob's blocking controls). Source: content-ratings page cited in §5.
