## 0. How to read and execute this plan

- Every coder step reads FIRST: `spec.md`, `design.md`, this file's block for its cluster, `carry-over.md`, `build-rules.md`, then `context.json` and its own `features/FEAT-xxx.json`. It implements ONLY its cluster, runs every verification command listed, writes `.agents/tasks/v1-build/verification-<cluster-id>.md` (commands + results + what was NOT verified), sets its FEAT `status: "completed"` and `findings`, makes ONE commit with the stated prefix, then `git pull --rebase origin main; git push origin main` (the Gemini Action also commits to main).
- Phase order A → B → C → D (spec section 12). Inside a phase: coder clusters in the listed order → one fix-and-review loop (max 2 iterations, pause on exhaustion, reviewer last, verdict file `review-phase-<x>.json`) → the phase ship step (reads the verdict file first; builds; screenshots; pushes; INFO message). Nothing ships without `"verdict": "APPROVED"`.
- Hard rules of `build-rules.md` apply to every step verbatim (PowerShell `;`, absolute paths, binary-file rule, secrets by name only, no `expo prebuild` after A01, disk check before Gradle/emulator, honesty: unbuilt = "not built").
- Owner steps never block a step (section 13); the only allowed owner-blocking pause is the missing `GEMINI_API_KEY` secret when a Gemini batch is required, and the disk-space warning before a Gradle build or emulator install when `(Get-PSDrive C).Free` < 4 GB (build-rules environment facts).
- Mandatory design-review items (section 3) are part of the cluster that owns the file; a coder who finds one unassigned implements it in its own cluster and records it.

## 9. Corpus pipeline (spec section 7, build-rules corpus rules)

- English master is authored in-repo by coders (A06–A08, B02, C02), one snippet per rule id, schema-validated, `review: "draft"`. UI strings are agent-written in all three languages, never machine-translated.
- `packages/content-tools/src/translate.ts` (CLI `--lang hi|bho|both --domains <list|all> --max-requests 450`): batches 12 snippets (lessons 1 per request) → `POST https://generativelanguage.googleapis.com/v1beta/openai/chat/completions`, `Authorization: Bearer <GEMINI_API_KEY>`, model `gemini-3.5-flash-lite`, `response_format: {type: "json_object"}` (retry once without it on HTTP 400), `max_tokens: 8000`, `reasoning_effort: "low"`, system prompt "single JSON object, no markdown fences, no prose"; user prompt = register rules (Hindi: respectful आप, Khari Boli, Sanskrit terms in Devanagari with a one-line gloss on first use; Bhojpuri: respectful रउआ/राउर, होला/करीं/बानी/नइखे, Devanagari, not Hindi-ised, no rustic slang, no Maithili forms, technical terms Latin on first mention) + forbidden content (outcome guarantees, health/medical claims, fear language, gendered assumptions, commercial remedies, accuracy %) + length midpoint with min/max ±40 % + "each item must keep its `id` and name the rule it explains" + the batch as JSON; response: fences stripped, first balanced `{…}` extracted, `finish_reason === "length"` or null content → error → the batch is halved and retried once; 429/5xx → exponential backoff ×3; stops at the request cap with a cursor; output `corpus/<domain>/<lang>.json` with `review: "draft"`; post-checks: Devanagari ratio ≥90 % of letters (hi), ≥85 % (bho, Latin technical terms allowed), forbidden-word lists per language (`forbidden.json`), length, id set equality; `diagnostic.json` scrubbed (redact `AIza[0-9A-Za-z_-]{30,}`, never log headers); `review-queue/<lang>-<batch>.md` with 50 random Bhojpuri snippets for the owner.
- `.github/workflows/corpus-translate.yml`: `workflow_dispatch` inputs `lang`, `domains`, `max_requests`; `permissions: contents: write`; setup-node 24; `npm ci`; run with `GEMINI_API_KEY: ${{ secrets.GEMINI_API_KEY }}`; upload `diagnostic.json` as an artifact; commit `chore(corpus): <lang> drafts for <domains>` and push to main (the Action's own bot identity).
- Dispatch protocol (A08, B02, C02): `gh secret list --repo Sudish007/shubhvela` → name present? else `send_message` WARNING asking the owner to run `gh secret set GEMINI_API_KEY --repo Sudish007/shubhvela` (he pastes the key into the hidden prompt) and wait; then `gh workflow run corpus-translate.yml --repo Sudish007/shubhvela -f lang=both -f domains=all -f max_requests=450; gh run watch --repo Sudish007/shubhvela <id>; git pull --rebase origin main; npm test -w packages/content`. Local fallback only if `$env:GEMINI_API_KEY` exists on this PC (same limits). Budget: batch A ≈ 85 requests/language (~960 snippets), B ≈ 25, C ≈ 45 — all under 450/day; a second day is used only on failures.
- Owner review: `send_message` INFO naming `packages/content-tools/review-queue/bho-<batch>.md` and `packages/content/ui/bho.json`; never wait. A reviewed batch is flipped to `review: "reviewed"` by the owner (or by a later step on the owner's written say-so).
