## Corpus rules (spec section 7)
English master text is authored in-repo by the coder (rule-grounded, one snippet per rule id, schema-validated, review: "draft"); Hindi and Bhojpuri are produced from the English master by the Gemini Action (translation + register rules) and flagged draft until the owner reviews 50 Bhojpuri snippets per batch (send_message INFO listing the file to review; do not block on it). UI strings (all keys) are agent-written in all three languages, never machine-translated. Register: Hindi respectful आप, standard Khari Boli; Bhojpuri respectful standard register (रउआ; होला/करीं/बानी/नइखे), Devanagari, not Hindi-ised, no rustic slang, no Maithili forms, technical terms Latin on first mention; English plain, no mysticism. Forbidden everywhere: outcome guarantees, health/medical claims, fear language, gendered assumptions, commercial remedies, accuracy percentages.

## UI rules (binding, spec section 8)
Four tabs Today · Family · Charts · Learn. Calm almanac look: paper-white light theme, ink text, one saffron/vermilion accent, one deep indigo; the chart is the hero graphic. HARD NO: gradients, glow, neon, galaxy/nebula backgrounds, particles, AI orbs/sparkles, stock illustrations, emoji in chrome, heavy shadows, autoplay media, fake numbers, testimonials, live tickers. Type: Tiro Devanagari Hindi (display) + Noto Sans Devanagari (body) for hi/bho, a humanist sans for en; body 17-18 sp, floor 12 sp, chart labels >=12 sp, tabular numerals; strings tested at +30% length; controls >=44 dp; WCAG AA; font-scale 1.3x must not clip; every stateful control shows its state in both themes; no two element boxes intersect inside a card at 360/390/412 dp. Every interpretive sentence has a 'Why?' showing rule + inputs; 'approx.' tags for unknown birth time or planets within 1 deg of a sign boundary; 'how this was computed' footer on reports; 'for reflection' on the journal. Web: gutters clamp(16px,4vw,96px), no container max-width below 2400 px, content box >=88% of viewport at >=1920, fluid type body ~17-18 px phones -> ~22 px at 2560, reading columns <=75-80ch with side rails, grids 1/2/3/4 columns at 390/1024/1920/2560, no horizontal overflow 320-2560, light default + persisted toggle.

## Review and pacing rules
- Design review: max 2 rounds, pause never abort. With 0 HIGH findings the reviewer must APPROVE and hand MEDIUM/NIT to the planner as mandatory implementation items.
- Code review per phase: fix loop capped at 2 iterations, pause never abort; reviewer last so its verdict gates the stop; '0 BLOCKING => approve' and write remaining MEDIUM/NIT into .agents/tasks/v1-build/carry-over.md (mandatory items for the next phase). Reviewers verify by running tests, building, and opening screenshots, never by reading code alone. Fix any hard-UI-rule violation found on ANY screen, in scope or not, and report it.
- Every ship/build step reads the phase verdict file first; if not APPROVED it does NOT ship: send_message warning and wait.
- The planner saves FULL self-contained step prompts in .agents/tasks/v1-build/workflow-tail.json and one features/FEAT-*.json per coder step (status pending/completed) so a dead run can be resumed from files.
- Coder steps: one feature cluster per step; READ FIRST = spec.md, design.md, plan.md block, carry-over.md, build-rules.md; implement ONLY that cluster; run every verification command and record commands + results in .agents/tasks/v1-build/verification-<phase-or-feat>.md; one commit per step with prefix feat(F12): ... (or chore/fix/docs); push to origin main after each phase's review approves (after each coder step is fine); if a finding would change user-visible behaviour not covered by the spec, send_message warning and wait.
