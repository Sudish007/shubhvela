## 4. Deviations and decisions (recorded, none user-visible beyond spec/design)

- **Gradle task name**: plan/FEAT say `:app:testReleaseUnitTest`; the AGP in this project generates no release unit-test variant, so `:app:testDebugUnitTest` is the equivalent (same `src/main` Kotlin, same `src/test`). C05/ship docs should use that name.
- **Background rewrite rule**: FEAT says "when fewer than 2 days remain"; implemented as "< 2 days remain OR file older than 12 h". Without the age rule the 36 h stale footer (P4) would show on day 2–5 of a week in which the user never opened the app although the data were still valid; with it, `writtenAt` stays fresh as long as the job runs and the footer means "background work has stopped" (Doze / force-stop). Cost: seven `goodHours` calls (~35 ms) per 12 h.
- **Kotlin → JS job start**: `WidgetScheduler.requestExtension` enqueues `expo.modules.backgroundtask.BackgroundTaskWork` directly (6 h debounce, KEEP). This is the library's own worker class with the input it expects (`appScopeKey` = package name), pinned by the expo-background-task version in package-lock; a rename would surface as a compile error, never silently.
- **`setWindow` on Android 12+**: the OS may stretch a 2-minute window to 10 minutes (AlarmManager docs); that is exactly what the opt-in "Exact widget updates" is for. The 15-min WorkManager job and `updatePeriodMillis` still bound the lag.
- **Hora word in the widget Now line**: the app's Now line reads "Mercury hora"; the file carries only the planet name per language, so the widget prints "Mercury" (one fewer word, same data).
- **Widget theme**: follows the host (system) `UI_MODE_NIGHT` via `res/values-night`, as design 10.2 says; the app's own Light/Dark toggle is recorded in the file (`theme`) but not applied to the widget.
- **UI_MODE / font scale**: text sizes come from `sp` dimens (already scaled); the N3 threshold uses `configuration.fontScale` explicitly; labels are also dropped when the measured text would exceed the span minus 10 dp.
- **Widget strings for the launcher picker** (`android:description`, `android:label`) follow the SYSTEM locale (res/values, -hi, -b+bho); everything the placed widget displays follows the APP language from the file.
