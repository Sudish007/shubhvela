## 4. Decisions and deviations recorded for the reviewer

1. **`LOAD_OPTIONS.maxTokens = 2048`, not the plan's 1024.** The module's Kotlin passes `maxTokens` as LiteRT-LM `maxNumTokens`, the session's prefill + decode cap. The grounded prompt (six rules ≈ 1,300 chars + chart JSON ≈ 1,100 + snippets) needs ≈ 1,400 tokens; at 1,024 every corpus snippet would be dropped and the answer could not cite a rule (spec F35 "prompt = chart JSON + corpus snippets + system rules"). Not user-visible; `PROMPT_CHAR_BUDGET` 5,600 chars leaves ≈ 600 tokens for the answer.
2. **SHA-256 via `expo-file-system` `File.digest('SHA-256')`** (native Kotlin `MessageDigest`, 64 KB streaming) instead of streaming the 2.6 GB file through `react-native-quick-crypto` in JS: same result, no 2 GB `ArrayBuffer` limit on Android, no JS-thread work. `react-native-quick-crypto` stays the backup's cipher.
3. **RAM threshold 5.5 GiB reported** (see §1 Device gate): Android never reports the marketed total; a strict 6 GiB would reject every 6 GB phone. The row prints the rounded GiB so the number shown and the decision agree.
4. **`.svb` file extension** (design 10.1 / FEAT) replaces C02's `.svbk` string in the three UI files and the Latin allow-list.
5. **`app_state.ask_model`** holds the paused download state + the verified flag (AppStateKey extended); **schema v3** adds `prashna.tz`.
6. **Deep-link festival year range** 1900–2100 = the engine tz table (plan P10); the festival detail route recomputes the date for the user's place as before.
7. Six UI keys added in en/hi/bho (listed in §1); all other copy is C02's.
