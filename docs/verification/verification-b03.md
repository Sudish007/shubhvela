## 3. Decisions a later step should know

- Grace period on-device: Play Billing exposes no "grace" flag to the client; during Play's grace period the purchase simply stays in `getAvailablePurchases` (Pro stays on). The cache state `grace` is set when expo-iap reports `isSuspendedAndroid` (billing issue, Billing 8.1+) or fires `subscriptionBillingIssueListener`; Pro stays on and Settings/Pro show "Payment issue — update your card in Play" until the next restore returns a healthy purchase (→ `active`) or none (→ `expired`, Pro off). Documented in `iap.ts`.
- `bannerFor(route)` returns `'anchored' | 'none'` (FEAT wording) instead of Phase A's `{ measuredHeight }` object; the measured height moved to `bannerHeightFor` / `useBannerHeight` (Screen's hook name unchanged).
- `BannerAdSize.ANCHORED_ADAPTIVE_BANNER` is marked deprecated in react-native-google-mobile-ads 17.4 (in favour of `LARGE_ANCHORED_ADAPTIVE_BANNER`); kept because design.md 5 specifies the anchored adaptive size and the strip height is measured anyway. Revisit if v18 removes it.
- Banner impressions count toward the 45 s spacing ("last ad of any kind"), so an interstitial right after a banner-carrying screen is usually blocked; this follows design.md 5 literally.
- The native ad is not session-gated (spec F38 / design.md 12 gate only banner and interstitial for sessions 1–3); it is gated by Pro and by the fold.
- Settings → Pro and purchases is a separate screen (`/settings/pro`) with a "Plans" row to `/pro`; the Pro screen stays reachable from the ad card's "Remove ads" and from every CapSheet "Go Pro".
