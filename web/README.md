# Shubhvela web companion

Static site generator for https://sudish007.github.io/shubhvela/ (spec F41–F43, design.md 9 and 10.10). Same engine and
content corpus as the app, three languages (`/en/`, `/hi/`, `/bho/`), light first paint with a persisted two-state theme
toggle, fluid wide layout with no container max-width, every number computed by `packages/engine` at build time.

```
npm run web:build          # -> web/dist (prints page count, dist size, elapsed)
node web/build.mjs --out <dir> --core-only --quiet
npm test -w web            # vitest: builds the core site into a temp dir and checks every page head, robots, sitemaps, OG
npm run typecheck -w web
```

## How the build works (`build.mjs`)

1. esbuild pre-bundles `packages/engine/src/index.ts` and `packages/content/src/index.ts` into `web/.cache/*.mjs`
   (Node, ESM) and imports them — no `tsx` at build time.
2. esbuild builds the browser bundle `src/client/kundli.ts` → `dist/assets/kundli.<hash>.js` (ESM, minified; deep
   engine imports so only kundli/chart-layout/dasha/yogas/share/tz/locale and the 331 web cities are bundled).
3. `src/tokens.css` (generated by `packages/content` gen-tokens — never edit) + `src/site.css` are minified and inlined in
   every page; the inline scripts in `src/client/*.js` (theme, toggle, ua, chart-scale, today-label, loader, 404 search)
   are minified and inlined too.
4. Engine data for the home page: the build's Asia/Kolkata civil day at New Delhi (panchang, chart of the sky at
   sunrise), the eight featured cities, the next six festivals. Pages print the date they were computed for;
   `today-label.js` adds "Today" only when the visitor's date matches.
5. Page plan (path → renderer) per language: home, kundli, `/m/`, download, privacy, terms, data-deletion, 404; root
   `/`, `/kundli/`, `/privacy/`, `/terms/`, `/data-deletion/`, `/download/` redirect to English, `/m/` is an English copy
   (the engine's language-less share URL), `404.html` is the Pages 404. Templates ask `site.has(path)` before linking, so
   a page type that is not in the build (D02's data pages) is rendered as text, never as a dead link.
6. `web/public/` is copied (robots.txt, `.nojekyll`, the brand run's `brand/` when present), the five TTFs are copied from
   `app/assets/fonts/`, OG images are rendered (`src/og/`, @resvg/resvg-js + sharp; composited over
   `public/brand/og-base.png` when it exists), sitemaps are written per language under `sitemap.xml`.

## Conventions

- Base path `/shubhvela/` everywhere (`src/config.mjs`); absolute URLs from `BASE_URL`.
- hreflang: `en`, `hi`, `x-default` only — never `bho` (Google accepts ISO 639-1 codes only); Bhojpuri pages keep
  `<html lang="bho">` and are linked from the language switcher and footer.
- `/<lang>/m/` is `noindex`, canonical to `/<lang>/kundli/`, excluded from sitemaps and disallowed in robots.txt (M8).
- Android-only `intent://…;S.browser_fallback_url=<Play or the download page>;end` buttons are shown only when
  `html[data-ua="android"]` (set by `ua.js`).
- Web-only strings live in `src/strings/<lang>.json` (identical key sets, register tests in `test/strings.test.mjs`);
  app UI strings come from `packages/content/ui/<lang>.json`. The Play Store URL goes into `site.playUrl` (all three
  files) once the listing exists; until then every Play button reads "Coming to Google Play".
- The chart SVG is `src/chart-svg.mjs` over the engine's `layout()` — the same geometry as the app and the PDF.
